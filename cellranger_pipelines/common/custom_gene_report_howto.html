Custom-gene (transgene) report: How to use it

Turns a cellranger count result plus transgene names into one or more self-contained HTML files. Open them offline in any browser — each file stands on its own. 

What it does

For each gene you name, it reports how that gene is expressed across the cells in one sample’s filtered feature matrix, and (in project mode) compares the samples. Per gene the report includes:

  • A status row (— EXPRESSED / SILENT / NO-ROW) plus detected cells, % of all cells, cells at ≥1 and ≥3 UMI, total transgene UMIs, reads from called cells (needs a BAM), mean and median UMI in positive cells, and the endogenous cell/UMI context.
  • Plots: UMI histogram, per-sample % positive and mean-UMI dot plot, positive/negative depth, and a UMAP coloured by the gene.
  • A read-start coverage track along the transgene contig.

The transgene row is the feature whose id equals the gene name (the appended-contig convention from the GECF custom genome). Any other feature rows carrying the same name are used as the endogenous reference.

What it needs

  • Required. A cellranger count outs folder — either one sample (Step 1) or a project folder holding several (Step 2) — and the gene name(s).
  • Optional (best-effort). An aligned BAM, which adds the coverage track and the “reads (called cells)” column; and a UMAP projection CSV from the analysis folder (auto-detected), which adds the UMAP panels. If either is missing, its panel shows “n/a” and everything else is still produced.
  • Python. Plotly is required to build the report; numpy/scipy are optional accelerators and samtools is only needed for the BAM. No environment setup is required: if the Python you launch the script with lacks the packages, it transparently re-runs itself under the lab’s brbseq conda environment (falling back to basecaller) with your original arguments — so plain python3 from any shell is fine, no conda activate. Set CGR_NO_ENV_SWITCH=1 to disable the auto-switch.
cd <folder containing> cellranger_pipelines/common
python3 custom_gene_report.py <options>

Step 1 — one sample

Give the parent of the count outs directory (the sample folder), the gene name(s), and where to write the report:

python custom_gene_report.py \
  --sample-dir /path/to/sample \
  --genes tRFP \
  -o /path/to/report

--genes takes either a single name or a space/comma-separated list, or a file with one gene per line (blank lines and # comments allowed). The transgene name must match the row id exactly as it appears in features.tsv.

Step 2 — all samples in a project

Point at the project root; every sample’s outs/filtered_feature_bc_matrix under it is picked up automatically, and the report adds an across-samples comparison:

python custom_gene_report.py \
  --project-dir /path/to/project \
  --genes tRFP \
  -o /path/to/report

Options

OptionMeaning
--sample-dirOne sample folder (parent of the count outs/ directory).
--project-dirProject root. All sample outs directories underneath are found and reported together.
--genesGene name(s): one per line in a file, or inline space/comma-separated exact ids. Required.
--min-umiPer-cell transgene-UMI threshold for the “detected” count and the EXPRESSED/SILENT status. Default 3.
--per-fileMax transgenes per detail file. When you list more than this many, the report splits into an index (tables for all genes + coverage tracks) plus numbered detail files this size (each carries the tables for its batch plus the plots). Default 50; 0 = one combined file.
--bamAligned BAM for the coverage track and the “reads (called cells)” column. If left unset it is auto-detected in the sample folder (possorted_genome_bam.bam and a few other common names); when no BAM is used, the reads column and the coverage track are shown as n/a.
-o, --outFolder to write the report into. Default is the input folder.
--versionPrint the version and exit.

The main file is always named custom_genes_<sample-or-project>.html in the output folder and is your starting point. With splitting on (see --per-file) it is the index: status tables for all transgenes, the coverage tracks, and links to the plot files custom_genes_<sample-or-project>_part01.html, _part02.html, …. Each file is fully self-contained — the plotting library is embedded in the files that contain plots — so any of them can be opened offline on its own.

Many transgenes? The report splits itself

The interactive plots scale with the number of transgenes, so one very long list in a single file can get too heavy to open. By default the report therefore splits into small files:

  • Index (the custom_genes_<sample-or-project>.html you open first): status tables for all transgenes, the coverage tracks, and a linked list of the plot files. It stays small no matter how many genes you list.
  • Plot detail files (_part01.html, _part02.html, …): the interactive plots for a batch of transgenes (50 per file by default). Each also carries the status tables for its batch and a link back to the index.

Use --per-file to change the batch size, and --per-file 0 to put everything back into one file. For one or a handful of transgenes there is no splitting at all — you just get the single report.

Reading the report

StatusMeaning
EXPRESSEDThe transgene row is present and at least one cell carries ≥ --min-umi UMI for it.
SILENTThe transgene row is present, but no cell reaches the threshold.
NO-ROWThe gene’s row is not in this sample’s feature table (nothing was appended/aligned for it).
Note. A row that is present but has no cells above the threshold is SILENT, not NO-ROW. Lowering --min-umi (e.g. to 1) re-evaluates the threshold— if a SILENT gene has any single-UMI cells it will then show as expressed at ≥1. Read counts and the coverage track depend on the BAM, and the UMAP panels depend on a UMAP projection file; without them those panels read “n/a” rather than changing the status.

See python3 common/custom_gene_report.py --help for the full command-line help.
