ARC (Multiome) pipeline: How to use it

Generate the script from your Excel file, adjust any settings you need, then run it.

ARC counts both a GEX (RNA) leg and an ATAC (chromatin) leg for each sample in a single cellranger-arc count run; the script handles that per-sample pairing for you. The pairing is name-driven, which matters in two places below: how sample names are written in the Excel sheet, and how sheet-less samples are added at the prompt.

Step 1: Generate the script

Run the generator with your run's Excel file (the one named after the run, e.g. AVT0571_Arianna_GECF Copy.xlsx):

python3 generate_cellranger_template_arc.py "AVT0571_Arianna_GECF Copy.xlsx"

Keep the file name in quotes, since the paths contain spaces. To combine several runs, list each file after the command in its own quotes; all samples go into one script.

python3 generate_cellranger_template_arc.py "AVT0571_….xlsx" "AVT0572_….xlsx"

Numbered sample folders (on by default)

Each sample's output folder is prefixed with its number in sample order (01_Name_of_sample, 02_…, 03_…), so the folders always appear in the order of your samples, even when the names themselves are not alphabetical (from 10 samples up the numbers continue 10, 11, …). If you prefer bare sample names without the number, add --no-number-prefix to the command:

python3 generate_cellranger_template_arc.py --no-number-prefix "AVT0571_Arianna_GECF Copy.xlsx"

Sample naming: how the GEX and ATAC legs are paired

The leg of every FASTQ is decided by the suffix of its sample name (case-insensitive):

  1. Name_ATAC (or name_atac) → chromatin (ATAC) leg.
  2. Name_GEX → RNA (GEX) leg.
  3. Any other name → counted as a GEX leg, by default.

Legs that share the same base name are grouped into one biologic sample and counted in a single cellranger-arc count: Sample1_GEX + Sample1_ATAC become one sample, Sample1. GEX-only and ATAC-only samples (a single leg) run the same way. The base name — the name without the leg suffix — is the sample name used everywhere in the outputs (output folder, libraries CSV, stats sheet): the suffix is a classification tag, never part of the result name.

Check the summary table. Right after the Samples question, the generator prints a Biologic samples table with a GEX count and an ATAC count per sample. A GEX+ATAC pair must show 1 and 1. If a multiome sample shows 2 GEX, 0 ATAC, its ATAC name is missing the _ATAC suffix and both legs will be processed as RNA — fix the name and regenerate before running the script.

It asks up to four questions, each answered by typing a number (or a path, or yes/no) and pressing enter. Not every run needs every question: the AVT one only appears if some samples couldn't have their run name auto-detected, and the data-folder one only appears if a sample name is ambiguous:

  1. AVT run name: only when some samples have no detected run name. Confirm the detected value, or type the correct AVT0XXX.
  2. Samples. Detected samples are listed. Keep the ones to run, drop others, and add samples that are missing from the sheet. How to answer each of its sub-prompts and how to leave it is detailed in How the Samples question works below.
  3. Data folder: shown only when a sample name exists in more than one run folder. Pick the correct one by number; a single match is used automatically.
  4. Genome: 1 human, 2 mouse (there is no combined reference for ARC). You can also type a full path to any other reference genome directory to use a custom one. The exact genome file/folder name inside each reference is resolved automatically, so no need to specify it.

How the Samples question works

The detected samples are listed with numbers; a GEX+ATAC pair appears as one entry (both legs folded together). Then:

  1. "Keep which samples?" — answer with numbers (1 3), exact sample names, or just press Enter to keep everything. s lists the FASTQ behind each entry.
  2. "Confirm this sample set? [y/N]" — y = the keep selection is final and you continue; N = answer the previous question again.
  3. "Add another sample that is not in the Excel sheet? [y/N]" — n = nothing more to add: this ends the Samples question and the generator moves on to the next one (data folder, then genome). With y, type the sample name, then the full path(s) of its FASTQ folder(s) — a lone Enter finishes that sample's folder list — and the same question comes back; keep answering it until you are done and close it with n.

In short: the selection ends when you answer y at "Confirm this sample set?" and n at "Add another sample?"; everything after that (the Biologic samples summary table, the data-folder question, the genome question) just continues on. N anywhere means "one step back, answer again".

A GEX+ATAC pair that is missing from the Excel must therefore be added twice: once as Sample1_GEX with the GEX folder, once as Sample1_ATAC with the ATAC folder. One name with both folders would make both legs GEX — the name suffix is the only thing that tells the two legs apart (see the naming rule above).

On success it writes cellranger-arc_AVT0XXX.sh in the current directory. That file is your pipeline.

Step 2: Edit the script

Open the generated script in a text editor. From the terminal, in the folder where the script was written, nano cellranger-arc_AVT0571.sh opens it (use the arrow keys to move around). To change a setting, edit the value inside the quotes on its line. When you are done, press Ctrl+O and hit Enter to save the file, then Ctrl+X to close nano, before running the pipeline. Most lines can stay as they are; the ones worth knowing are below.

Run-wide (all samples)

SettingMeaning
keepdataKeep the local working folder after the run. Default no is correct, since the results are already in the central archive. Set yes only to keep a local copy too.
max_parallelNumber of samples counted simultaneously. 1 is serial. Default 3 suits a large server (like ptegsrv3); lower it for a smaller box or when other heavy jobs are running.
localcoresMaximum CPU cores per sample (applies to all samples). Default 32.
localmemMaximum memory in GB per sample (applies to all samples). Default 126.
scratch_rootWhere cellranger-arc count writes its working output (fixed convention on the analysis server; change it only if the mount differs on your box).
REFPATHThe reference picked in Step 1. Change only if the wrong one was selected.
server_folder_nameOutput folder name, prefilled with run + user + timestamp. Leave as is unless renaming is wanted.
NGSruns_archiveCentral archive the results are copied to at the end (fixed shared target; leave as is).
fastq_<#>_<library>Data location per sample leg (the GEX fastq and the ATAC fastq), prefilled. A FIXME marker instead of a real path means that leaf folder could not be resolved; set the real folder there before running.
Note. localcores and localmem apply to every sample, and up to max_parallel samples run at the same time, so the box effectively needs max_parallel × (cores, memory). Example: at the defaults, 3 concurrent samples × 32 cores / 126 GB needs roughly 96 cores / 378 GB of free space. If the run is bigger than that, lower max_parallel or the cores/memory values.

Per-sample (the suffix is the sample number)

Leave a value blank to use the built-in default. The _<#> matches the sample to change.

SettingMeaning
create_bam_<#>true (default) also writes an aligned BAM for this sample. Set false to skip it (faster, smaller output).
gex_exclude_introns_<#>Blank (default) keeps the cellranger-arc behaviour, so intronic GEX reads are counted too. Any value (e.g. true) adds --gex-exclude-introns for this sample, counting only exonic GEX reads. Feeds the "Include introns?" column of the stats sheet.
cell_annotation_model_<#>auto (default) lets cellranger-arc choose the cell-annotation model. Name a specific model, or leave blank, if you have one in mind.
custom_options_<#>Additional flags for this sample, written in full inside the quotes (e.g. --nosecondary --localvmem=300).

Step 3: Run it

From the same directory as the script:

./cellranger-arc_AVT0571.sh

The ./ prefix is required to run a script from the current directory. To run it in the background and capture output to a log:

nohup bash cellranger-arc_AVT0571.sh > AVT0571.log

It checks the settings first (e.g. that the reference folder exists). Then it counts the samples. They run in a rolling pool of max_parallel (default 3) at a time. Each sample reports [ OK ] or [ FAIL ]. A failing sample does not block the rest.

When the counting is done, the script collects the results. It merges every sample's summary table into one summary_metrics.csv. It writes the central TSO% report tso_report.txt on the GEX leg — one section per avid run (every GEX-leg fastq is measured, not just the first; ATAC-only samples are skipped). It writes a per-run stats file AVT0XXX_stats.xlsx into the run folder. One sheet per modality (GEX and ATAC). One row per sample per modality. Each row carries the official sample name, the GECF library label, the seq. run, the fastq code, the cellranger-arc version, the genome assembly, and the incl/introns setting.

Then it wraps up. It collects the web summaries (the joint Multiome page, plus the GEX-only and ATAC-only pages). It stores a copy of this script and its checksums in the run folder. It copies everything to the shared archive. With keepdata="no", it removes the local working folder. That removal is normal.

The stats step can never break the run. Without an Excel library, it writes the same data as two CSVs. Without a Python interpreter, it warns and skips.

Follow progress directly in the terminal, or via AVT0571.log if it is running in the background.
