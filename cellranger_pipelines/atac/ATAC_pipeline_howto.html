ATAC pipeline: How to use it

Generate the script from your Excel file, adjust any settings you need, then run it.

ATAC (scATAC) is the chromatin-accessibility-only pipeline. Each sample is counted by a single cellranger-atac count run; there is no RNA leg.

Step 1: Generate the script

Run the generator with your run's Excel file (the one named after the run, e.g. AVT0571_Arianna_GECF Copy.xlsx):

python3 generate_cellranger_template_atac.py "AVT0571_Arianna_GECF Copy.xlsx"

Keep the file name in quotes, since the paths contain spaces. To combine several runs, list each file after the command in its own quotes; all samples go into one script.

python3 generate_cellranger_template_atac.py "AVT0571_….xlsx" "AVT0572_….xlsx"

Numbered sample folders (on by default)

Each sample's output folder is prefixed with its number in sample order (01_Name_of_sample, 02_…, 03_…), so the folders always appear in the order of your samples, even when the names themselves are not alphabetical (from 10 samples up the numbers continue 10, 11, …). If you prefer bare sample names without the number, add --no-number-prefix to the command:

python3 generate_cellranger_template_atac.py --no-number-prefix "AVT0571_Arianna_GECF Copy.xlsx"

Combining several Excel files: the numbering follows the sample order from your files. If all files list the samples in the same order, that order is used. If the files list them differently, the order of the first file (the one listed first on the command) is used, and samples that only appear in the later files are added at the end.

Asks up to 4 questions, each answered by typing a number (or a path) and pressing enter. Not every run needs every question: the AVT ones only appear for samples without an auto-detected run name, and the data-folder one only appears if a sample name is ambiguous:

  1. AVT run name: one question per sample without a detected run name — the prompt shows the sample name and its FASTQ folder. Confirm the suggested value if one is shown, or type the correct AVT0XXX.
  2. Samples. Detected samples are listed. Keep the ones to run; a sample missing from the list can be added by its full data-folder path. Ends with a summary of the final sample list.
  3. Data folder: shown only when a sample name exists in more than one run folder. Pick the correct one by number; a single match is used automatically.
  4. Genome: 1 human (Human ATAC), 2 mouse (Mouse ATAC). You can also type a full path to any other reference genome directory to use a custom one. The exact genome file/folder name inside the reference is resolved automatically, so no need to specify it.

On success it writes cellranger-atac_AVT0XXX.sh in the current directory. That file is your pipeline.

Step 2: Edit the script

Open the generated script in a text editor. From the terminal, in the folder where the script was written, nano cellranger-atac_AVT0571.sh opens it (use the arrow keys to move around). To change a setting, edit the value inside the quotes on its line. When you are done, press Ctrl+O and hit Enter to save the file, then Ctrl+X to close nano, before running the pipeline. Most lines can stay as they are; the ones worth knowing are below.

Run-wide (all samples)

SettingMeaning
keepdataKeep the local working folder after the run. Default no is correct, since the results are already in the central archive. Set yes only to keep a local copy too.
max_parallelNumber of samples counted simultaneously. 1 is serial. Default 3 suits a large server (like ptegsrv3); lower it for a smaller box or when other heavy jobs are running.
localcoresMaximum CPU cores per sample (applies to all samples). Default 32.
localmemMaximum memory in GB per sample (applies to all samples). Default 126.
scratch_rootWhere cellranger-atac count writes its working output (fixed convention on the analysis server; change it only if the mount differs on your box).
reference_genomeThe reference picked in Step 1. Change only if the wrong one was selected.
server_folder_nameOutput folder name, prefilled with run + user + timestamp. Leave as is unless renaming is wanted.
NGSruns_archiveCentral archive the results are copied to at the end (fixed shared target; leave as is).
fastq_<#>_<j>Data location per sample (one line per FASTQ file), prefilled. A FIXME_LOCATE_ marker instead of a real path means that leaf folder could not be resolved; set the real folder there before running.
Note. localcores and localmem apply to every sample, and up to max_parallel samples run at the same time, so the box effectively needs max_parallel × (cores, memory). Example: at the defaults, 3 concurrent samples × 32 cores / 126 GB needs roughly 96 cores / 378 GB of free space. If the run is bigger than that, lower max_parallel or the cores/memory values.

Per-sample (the suffix is the sample number)

Leave a value blank to use the built-in default (or to drop that flag entirely). The _<#> matches the sample to change.

SettingMeaning
custom_options_<#>Additional flags for this sample, written in full inside the quotes (e.g. --peaks=/refs/peaks.bed for peak calling against a pre-built peak set).

Step 3: Run it

From the same directory as the script:

./cellranger-atac_AVT0571.sh

The ./ prefix is required to run a script from the current directory. To run it in the background and capture output to a log:

nohup bash cellranger-atac_AVT0571.sh > AVT0571.log

It checks the settings first (e.g. that the reference folder exists), then counts each sample in a rolling pool of max_parallel (default 3). Each sample reports [OK] or [FAIL]; a failing sample does not block the rest. When the counting is done it merges every sample's summary table into one summary_metrics.csv, collects each sample's web summary page, stores a copy of this script and its checksums in the run folder, copies everything to the shared archive, and removes the local working folder (when keepdata="no"). That removal is normal.

Follow progress directly in the terminal, or via AVT0571.log if it is running in the background.
